# Токенизация на уровне слов

Токенизация — это процесс преобразования исходного текста в последовательность дискретных целочисленных идентификаторов, которые может обрабатывать нейронная сеть. Это самый первый этап любого конвейера обработки естественного языка, который устраняет разрыв между строками, понятными человеку, и числовыми тензорами, с которыми работают модели. Токенизация на уровне слов — самая простая стратегия, при которой каждое слово, разделенное пробелами, рассматривается как отдельный токен.

Токенизатор на уровне слов выполняет две взаимодополняющие операции. Кодирование принимает необработанную строку, приводит ее к нижнему регистру, разбивает на части по пробелам и сопоставляет каждое полученное слово с уникальным целочисленным идентификатором с помощью фиксированного словаря. Декодирование выполняет обратный процесс, преобразуя последовательность целочисленных идентификаторов обратно в строку, понятную человеку, путем поиска каждого идентификатора в обратном сопоставлении и объединения слов с помощью пробелов.

Словарь формируется заранее на основе обучающего корпуса. Каждое уникальное слово получает постоянный целочисленный идентификатор. Слова, встречающиеся во время логического вывода, но не встречавшиеся во время обучения, сопоставляются со специальным токеном «неизвестный». Это основной компромисс: простота в ущерб жесткому словарю, который не может обрабатывать новые слова. Токенизатор поддерживает детерминированное биективное сопоставление:

word_to_id : string → integer  |||| id_to_word : integer → string

## Ключевые уравнения

### Функция кодирования для одного слова

encode(w) = system!
{
    word_to_id[w] if w belongs V;
    1 otherwise (UNK);
}

### специальные токены

PAD, UNK, BOS, EOS

Обычные словарные слова получают идентификаторы, начинающиеся с 4. Если уникальные слова из обучающего корпуса, отсортированные в алфавитном порядке, — это w_0, w_1, ..., w_n-1

word_to_id[w_i]=i+4 for i=0,1,…,n−1

decode(k)=id_to_word[k]

## Формирование словаря

Формирование словаря — это детерминированная многоэтапная процедура, которую необходимо выполнять в строго определенном порядке, чтобы обеспечить единообразие присвоения идентификаторов.

Шаг 1. Инициализация специальных токенов. Зарезервируйте первые четыре идентификатора: PAD = 0, UNK = 1, BOS = 2, EOS = 3. Это жестко заданные константы, которые никогда не выводятся из обучающих данных.

Шаг 2. Приведение всего текста к нижнему регистру. Каждое обучающее предложение преобразуется в нижний регистр, чтобы слова «The», «the» и «THE» соответствовали одному и тому же токену. Без этого в словаре будут лишние дубликаты, отличающиеся только заглавными буквами.

Шаг 3. Разделение по пробелам. Каждое предложение в нижнем регистре разбивается на слова с помощью пробела в качестве разделителя. Знаки препинания, присоединенные к слову (например, «hello»,) остаются частью этого токена.

Шаг 4. Соберите уникальные слова. Пройдитесь по всем словам во всех обучающих предложениях и соберите набор уникальных слов. Дубликаты исключаются.

Шаг 5. Сортировка по алфавиту. Уникальные слова сортируются в лексикографическом порядке. Сортировка крайне важна для воспроизводимости результатов: без нее рандомизация хэша или порядок вставки могут привести к тому, что в разных прогонах будут присваиваться разные идентификаторы.

Шаг 6. Присвоение идентификаторов. Пройдитесь по отсортированному списку и присвойте идентификаторы, начиная с 4. Первое слово в алфавитном порядке получает идентификатор 4, второе — 5 и так далее.

В результате получается прямой словарь word_to_id и обратный словарь id_to_word, оба включают специальные токены.

## Специальные токены

Специальные токены выполняют структурные функции, которые не могут выполнять обычные слова. Каждый из них существует по определенной технической причине, связанной с тем, как нейронные сети обрабатывают последовательности.

PAD (ID = 0)
Нейронные сети обрабатывают пакеты последовательностей одновременно, но последовательности редко имеют одинаковую длину. Padding заполняет более короткие последовательности, чтобы их можно было объединить в один тензор. PAD по соглашению присваивается идентификатор 0, что упрощает маскирование: бинарная маска для позиций без заполнения — это просто проверка на ненулевые идентификаторы. Во время внимания позиции заполнения маскируются.

UNK (ID = 1)
Неизвестный токен — это резервный вариант для любого слова, которого нет в словаре. Все слова, отсутствующие в словаре (OOV), приравниваются к одному и тому же идентификатору UNK, что приводит к потере всей информации об исходном слове. Эта потеря информации — главный недостаток токенизации на уровне слов.

BOS (ID = 2)
Токен начало последовательности обозначает начало последовательности. В авторегрессионных моделях BOS служит начальным входным токеном, на основе которого модель генерирует первое реальное слово. Без него модель не сможет отличить «первый токен новой последовательности» от токена продолжения.

EOS (ID = 3)
The конец последовательности — токен, обозначающий конец последовательности. При авторегрессионной генерации предсказание EOS указывает алгоритму декодирования на необходимость остановиться. В исходном варианте Transformer EOS на стороне источника сигнализирует о завершении ввода, а EOS на стороне цели — о завершении перевода.

## Кодирование: преобразование текста в идентификаторы

Кодирование преобразует необработанную текстовую строку в список целочисленных идентификаторов в три этапа.

Шаг 1 — приведение к нижнему регистру. Приведение всей входной строки к нижнему регистру в соответствии с нормализацией, примененной при формировании словаря.

Шаг 2 — разделение. Разделение строки в нижнем регистре по пробелам для получения списка слов.

Шаг 3 — поиск. Для каждого слова выполняется поиск в word_to_id. Если слово найдено, используется его идентификатор. Если идентификатор не найден, используйте идентификатор UNK (
1
1).

На выходе получается список целых чисел, длина которого равна количеству слов. BOS и EOS не добавляются автоматически; необходимость их добавления зависит от используемой модели.

## Декодирование: преобразование идентификаторов в текст

При декодировании список целочисленных идентификаторов преобразуется обратно в строку, понятную человеку.

Шаг 1 — поиск. Для каждого идентификатора найдите соответствующую строку в id_to_word . Специальные идентификаторы токенов сопоставляются с их строковыми представлениями (PAD, UNK, BOS, EOS).

Шаг 2 — объединение. Объедините все полученные строки, вставив пробел между каждой парой.

Декодирование не является полной противоположностью кодирования. Любое слово, которое при кодировании было сопоставлено с UNK, декодируется как буквальная строка UNK, а не как исходное слово. Исходное слово безвозвратно утеряно.

## Контекст статьи

В оригинальной статье о Transformer «Attention Is All You Need» (Васвани и др., 2017) не использовалась токенизация на уровне слов. Авторы использовали байтовое парное кодирование (Byte Pair Encoding, BPE) с общим исходно-целевым словарем, содержащим около 37 000 токенов для перевода с английского на немецкий и 32 000 токенов для перевода с английского на французский.

Выбор был сделан неслучайно. Машинный перевод работает с двумя языками одновременно, и словари на уровне слов для обоих языков были бы огромными. BPE сжимает словарь, представляя редкие слова в виде последовательностей распространенных подслов, что полностью устраняет проблему отсутствия слов в словаре.

Примечательно, что Васвани и соавторы... использовали общий словарь: единый словарь BPE, составленный на основе объединенных двуязычных данных. Это позволило кодировщику и декодировщику использовать одну и ту же матрицу эмбеддингов, что сократило количество параметров и позволило использовать межъязыковое совпадение подслов.

Токенизация на уровне слов остается основополагающим методом, от которого отталкиваются все методы токенизации на уровне подслов. Каждый токенизатор подслов по-прежнему создает последовательности целочисленных идентификаторов, обрабатывает специальные токены и поддерживает симметрию кодирования и декодирования.

Числовой пример
Рассмотрим два обучающих предложения:

Предложение 1: «The cat sat on the mat»
Предложение 2: «The dog sat on the log»
Создание словаря
В нижнем регистре: оба предложения превращаются в «the cat sat on the mat» и «the dog sat on the log».

Соберите уникальные слова: {cat, dog, log, mat, on, sat, the}. "the" встречается четыре раза, но считается за одно слово.

Отсортируйте по алфавиту: [cat, dog, log, mat, on, sat, the].

Присвойте идентификаторы, начиная с 4:

PAD = 0
UNK = 1
BOS = 2
EOS = 3

cat = 4
dog = 5
log = 6
mat = 7
on = 8
sat = 9
the = 10

Общий размер словаря: 7+4=11.
Кодирование известного предложения
Входные данные: "The cat sat on the mat"

В нижнем регистре: "the cat sat on the mat"

Разбить на слова: ["the", "cat", "sat", "on", "the", "mat"]

Поиск каждого слова: [10, 4, 9, 8, 10, 7]

Все слова есть в словаре, поэтому токены UNK не появляются.

### Кодирование предложения с неизвестными словами

Входные данные: "The bird sat on the log"

В нижнем регистре: "the bird sat on the log"

Разделить: ["the", "bird", "sat", "on", "the", "log"]

Поиск: "the" = 10, "bird" не входит в словарь = 1 (UNK), "sat" = 9, "on" = 8, "the" = 10, "log" = 6.

Результат: [10, 1, 9, 8, 10, 6]

"bird" никогда не встречалось во время обучения, поэтому оно заменяется на UNK.

### Расшифровка

Входные идентификаторы: [10, 1, 9, 8, 10, 6]

Поиск: 10 = "the", 1 = "UNK", 9 = "sat", 8 = "on", 10 = "the", 6 = "log".

Соедините словами: "the UNK sat on the log"

"bird"" было заменено на UNK, что свидетельствует о необратимой потере информации.

## Токенизация на уровне слов и на уровне подслов

Токенизация на уровне слов и на уровне подслов предполагает принципиально разные компромиссы в спектре детализации.

Токенизация на уровне слов
Размер словаря: увеличивается по мере роста корпуса. В английском языке активно используется более 170 000 слов. Словарь из более чем 100 000 токенов означает, что одна только матрица эмбеддингов занимает сотни мегабайт.
Проблема отсутствия слов в словаре: любое слово, которого нет в словаре, обозначается как UNK. Катастрофически плохо для морфологически богатых языков (турецкий, финский), имен собственных и опечаток.
Семантика токенов: Каждый токен представляет собой целое слово, что делает словарь понятным для человека.
Длина последовательности: Создает самые короткие последовательности (один токен на слово), минимизируя затраты на внимание

O(n**2).
Токенизация по подсловам (BPE, WordPiece, униграмма)
Размер словаря: обычно от 30 000 до 50 000 токенов, независимо от размера корпуса. GPT-2 использует 50 257 токенов BPE; BERT использует 30 522 токена WordPiece.
Нет проблемы с новыми словами: любое слово разбивается на известные подслова. "transformerification" превращается в ["transform", "##eri", "##fication"] а не UNK.
Морфологическое разделение: "run", "running", "runner" имеют общее подслово "run", что позволяет обобщать варианты.
Длина последовательности: Более длинные последовательности, чем на уровне слов, поскольку редкие слова разбиваются на несколько частей, что увеличивает n в O(n**2) внимания.
Авторы статьи о Transformer выбрали BPE, потому что при переводе необходимо учитывать редкие слова в обоих языках. Токенизатор на уровне слов для англо-немецкого перевода потребовал бы более 200 000 токенов, по-прежнему страдал бы от отсутствия в словаре имен собственных и тратил бы ресурсы на редкие слова. BPE с 37 000 общих токенов решил все три проблемы.

## Подводные камни

Забывают переводить в нижний регистр перед поиском в словаре. Если словарь был создан на основе текста в нижнем регистре, но при кодировании регистр не учитывается, то «The» не будет соответствовать «the» и будет отображаться как UNK. Это скрытая ошибка: модель работает, но получает искаженные входные данные с повышенным процентом UNK.

Неправильный порядок сортировки приводит к несогласованности идентификаторов. Если уникальные слова не отсортированы перед присвоением идентификаторов, сопоставление становится недетерминированным. В Python set нет гарантированного порядка итераций. При двух проверках одних и тех же данных могут быть получены разные словари.

Не обрабатываются неизвестные слова при кодировании. Если функция кодирования выполняет прямой доступ к словарю без запасного варианта, то при первом слове, отсутствующем в словаре, возникает ошибка KeyError. В правильной реализации используется .get() с идентификатором UNK по умолчанию.

Отклонение на единицу в идентификаторах после специальных токенов. Первое обычное слово должно получить идентификатор 4, поскольку идентификаторы 0 — 3 зарезервированы. Распространенная ошибка — начинать нумерацию с 0, перезаписывая идентификаторы специальных токенов. Это приводит к коллизиям, когда обычное слово имеет тот же идентификатор, что и PAD или UNK, что незаметно приводит к искажению всей кодировки.

Чувствительность к регистру при обратном сопоставлении. Словарь id_to_word должен сопоставлять идентификаторы со словами в нижнем регистре. Если исходный текст не преобразован в нижний регистр, преобразование в обратном направлении не сработает: decode(encode(lowercase(text))) не будет равно lowercase(text).

Обработка специальных строк-маркеров как обычных слов. Если обучающий корпус содержит буквенные строки, такие как "PAD" или "UNK", их не следует добавлять в обычный словарь во второй раз, иначе дублирование записей с разными идентификаторами приведет к неоднозначности кодирования.

При условии, что пунктуация учтена. Базовая токенизация на уровне слов разделяет текст только по пробелам. "hello, world!" преобразуется в ["hello,", "world!"], а не в ["hello", ",", "world", "!"]. Слова, связанные с пунктуацией, становятся отдельными словарными статьями, что приводит к неожиданному увеличению объема данных.
